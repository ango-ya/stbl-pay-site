入金消込は自動化できる？：銀行 API・バーチャル口座でも残る手作業

入金消込は、銀行 API で明細を自動で取り込み、取引先や注文ごとのバーチャル口座や、照合のルール・消込のシステムを組み合わせれば、多くの入金を自動で照合できます。ただし、銀行 API は明細を速く取る手段で、振込に載る手がかり（振込依頼人名・金額・日付など）を増やすものではありません。過不足のある入金や、照合できない入金は、決めたルールで処理するか、購入者に連絡して確かめる作業が残ります。返金の手順も、サービスによって違います。消込そのものをなくすには、注文と支払いが最初から結びつく受け取り方が要ります。

3 行でわかる

  • 銀行 API・バーチャル口座・入金の通知・消込のシステムを組み合わせれば、多くの入金は自動で照合できます。
  • 銀行 API は明細を速く取る手段で、手がかりは増えません。過不足のある入金や照合できない入金は、ルールで処理するか購入者に確かめます。
  • 消込をなくすには、注文と支払いが最初から結びつき、過不足がお店の受け取りに及ばない受け取り方が要ります。

自動化できること・例外として残ること

すてぶるくん：消込って、全部自動にできるの？

すてぶるちゃん：組み合わせしだいで、多くの入金は自動で照合できます。過不足のある入金や照合できない入金は、例外として残ります。

入金消込は、口座に入ったお金がどの注文や請求の支払いかを突き合わせ、注文や請求を入金済みにしていく作業です。基本は、入金消込とはで解説しています。

銀行 API で明細を取り込み、バーチャル口座や照合のルール、消込のシステムを組み合わせれば、多くの入金は自動で照合できます。一方で、過不足のある入金や照合できない入金、返金は、例外として残ります。作業ごとの範囲は、次の表のとおりです。

銀行 API とは

銀行 API は、銀行の外のシステムが、銀行の口座の情報を取ったり、振込を指示したりするための窓口です。会計ソフトや消込のシステムが、明細を自動で取り込めるのは、この窓口があるからです。

日本では、2017年5月26日に銀行法等の一部を改正する法律が成立し、6月2日に公布されました。電子決済等代行業（会計ソフトや家計簿アプリのように、銀行とお客さまのあいだに立つサービス）の登録制が入り、体制の整備などを求める制度の枠組みが整いました。施行は 2018年6月1日です[2]。この改正で、銀行には、オープン API の体制整備に努めることが求められました[1]。

API には、口座の情報を取るものと、支払いや送金を指示するものがあります[1]。消込に使うのは、入金の明細を取るほうです。どの API を使えるかは、銀行と口座の種類ごとに確かめる必要があります。

銀行 API で取れる明細の中身

すてぶるくん：API なら、注文番号も取れるの？

すてぶるちゃん：取れるのは、振込に載った情報です。調べた銀行の仕様書には、注文番号の専用の欄がありませんでした。

銀行 API を使うと、明細を速く、自動で取れます。手で銀行の画面から取りに行く手間はなくなります。

では、取れる明細には何が載っているのでしょうか。例として、GMO あおぞらネット銀行のオープン API の仕様書（法人口座編）を見ます。振込入金明細には、依頼人名（最大 48 文字）、EDI 情報（最大 20 文字）、仕向金融機関名カナ（最大 30 文字）、仕向支店名カナ（最大 15 文字）などの項目があります[3]。依頼人名は、振り込んだ人の名前です。仕向金融機関と仕向支店は、振り込んだ側の銀行と支店です。EDI 情報は、振込に添えられる短い文字の欄です。

注文番号を入れる専用の欄は、項目にありません。EDI 情報に番号を載せてもらう運用はできますが、振り込む人が入れた場合だけ入ります[3]。照合の手がかりは、振込に載る依頼人名・EDI 情報・金額・日付、仕向けの銀行と支店などです。API は明細を速く取る手段で、この手がかりを増やすものではありません。

現行の項目や利用条件は、銀行に確かめてください。他の銀行の項目は、この解説では確かめていません。

全銀 EDI（ZEDI）で解決しないのか

全銀 EDI システム（ZEDI）は、振込に添える情報を増やす仕組みです。2018年12月25日に稼動を開始しました[5]。支払通知番号や請求書番号などを添えられるようになります[5]。EDI 情報は、全銀の固定長形式では 20 桁でしたが、XML 形式では 140 桁×最大 500 行に増えました[6]。

ただし、EDI 情報を XML で付けて送るサービスは、総合振込（企業がまとめて振り込む仕組み）向けです。XML の明細を受け取って見る側も、全銀 EDI システムに対応したサービスを使う必要があります。たとえば三菱 UFJ 銀行の 2024年4月の案内では、全銀 XML サービスは、全銀 VALUX・全銀 ADP サービスのオプションで、料金がかかります[6]。

全国銀行協会の 2019年12月の資料は、当時の利用明細件数が依然として低位で、利用が進んでいるとは言い難い状況だとしていました。課題には、金融 EDI 情報の入力の負担が挙げられていました[7]。いまの利用状況は、この解説では確かめられていません。

ZEDI は、企業どうしの振込のための仕組みです。ネットショップの購入者の振込に、注文番号が付いて届く仕組みではありません。個人の振込で使えるかは、この解説では確かめていません。

バーチャル口座で減らせること・残ること

すてぶるくん：注文ごとに口座を分ければ、ずれない？

すてぶるちゃん：どの注文かは分かりやすくなります。でも、額が足りない入金や多い入金は残ります。

代表口座 1 つで振込を受けると、明細には振込人名が出るため、請求の情報と振込人名が違うと照合できません。たとえば、請求先の会社の代わりに社長の名義で、また本人の代わりに家族の名義で振り込まれる場合です[8]。

バーチャル口座は、1 つの代表口座の下に、注文や取引先ごとの専用の口座番号を作る仕組みです。どの口座番号に振り込まれたかで、注文ごとの口座なら注文が、取引先ごとの口座なら取引先が分かります。取引先ごとの口座では、どの請求の分かを別に照合します。名前の表記に頼らないぶん、名義の違いによる照合のずれは減らせます。

  • ドコモSMTBネット銀行（旧・住信SBIネット銀行）の振込入金専用口座。法人口座を開いたあとに申し込む、法人向けの商品です。請求書ごと・取引先ごとに専用の口座番号を割り当てられます。手数料は無料と記載され、1 つの代表口座につき 1,000 口座まで作れます。入金は代表口座に振り替えられ、明細の内容欄に、専用口座の番号と振込人名の頭 5 文字が出ます。ただし、一部の振込はこの表示にならない場合があります[8]。
  • Stripe の日本の銀行振込。顧客ごとに仮想口座が作られ[10]、この口座番号が自動の消し込みに使われます[9]。日本では、振込の参照番号は使われません[10]。日本円の消し込みでは、仮想口座で顧客を特定したうえで、顧客の現金残高と金額が一致する 1〜5 件の請求書・PaymentIntent の組み合わせを探します。なければ、全額を充てられる請求書に確定日時の古い順に充て、残りを PaymentIntent の確認日時の古い順に充てます[11]。

バーチャル口座への入金を、銀行が通知で知らせる仕組みもあります。GMO あおぞらネット銀行の仕様書には、振込入金口座（バーチャル口座）に入金があると、その明細を銀行のシステムから登録した送り先へ送る通知（Webhook）があります。個人事業主口座と法人口座向けの機能です[4]。バーチャル口座と通知を組み合わせれば、入金をすぐに知って照合できます。

ただし、同じ仕様書には、通知の順番は保証されないこと、正常に受け取ったと確認できないと同じ通知が重ねて届くことがあること、障害で失われた通知は入金明細の照会の API で取り直すことが書かれています[4]。重なった通知や取りこぼしへの備えは要ります。

口座を分けても、残るものがあります。Stripe では、過払いは顧客の残高に残ります[10]。照合されない資金が 75 日を超えて残ると、顧客の銀行口座への返金が自動で試みられ、90 日を過ぎても残っていれば Stripe の残高に移されます[11]。ドキュメントには、顧客の残高が消し込まれているかを、お店の責任で確かめる必要があると書かれています[11]。銀行口座へ返金するには、購入者の口座の情報が要ります。Stripe では、振込のときに受け取った口座の情報を使い、無いときやあいまいなときは Stripe が購入者にメールで尋ねます[14]。

消込のシステム・AI 消込

請求書や入金の管理のシステムには、消込を自動にするものがあります。

ROBOT PAYMENT の請求管理ロボは、バーチャル口座で、振込人名が一致しなくても取引先を特定するとうたっています（同社の公表）[12]。過剰の入金は、繰越待ちとして登録し、次回の請求で差し引けます。複数の請求に対するまとめての入金も、自動で消し込めます。過不足やまとめての振込を、決めたルールで処理する例です。自動の消込に失敗した請求は抜き出され、人が手で紐付けて消し込みます。名義が違って失敗した口座名義を覚え、一度手で紐付けたものは次回から自動で消し込む機能（AI 消込学習）もあります[15]。精度をうたう数字もありますが、ベンダーの公表値で、第三者が確かめたものではないため、ここでは取り上げません。

マネーフォワード クラウド債権管理では、入金のデータと請求のデータを条件で照合し、一括で消し込みます。照合の条件に合わない行は、人が個別に消し込む手順です。入金額が請求額を上回る場合は、過入金の分を前受と入金残のどちらで記録するかを人が選びます。名前が似た入金や金額が一致する入金を、AI が消込の候補として示す機能もあります[13]。

こうしたシステムは、条件に合う入金を速く片づけ、人が見る入金を絞ります。

例外として残ること

ここまでの方法で、多くの入金は自動で照合できます。それでも、銀行 API だけでは、注文や請求との対応が決まらない入金があります。

  • 過不足のある入金。振込手数料を差し引いた額や、多く振り込まれた額です。
  • 照合できない入金。名義が注文者と違う振込や、どの注文の分か分からないまとめての振込です。
  • 返金。銀行口座へ返金するには、購入者の口座の情報が要ります。Stripe では、振込のときに受け取った口座の情報を使い、無いときやあいまいなときは Stripe が購入者にメールで尋ねます[14]。

例外の入金は、決めたルールで処理するか、購入者に連絡して確かめます。例外の扱いは、サービスごとに違います。ルールで処理する例は、Stripe の決まった順序で充てる仕組みや、請求管理ロボの繰越待ち（次回の請求で差し引く）です。ルールに当てはまらない入金は、人が確かめることになります。

消込そのものをなくすには

ここまでの方法は、届いた入金を、あとから注文に当てはめます。そのため、当てはめられない入金が例外として残ります。消込をなくすには、当てはめる作業がいらない形にします。次の 3 つがそろうと、銀行の入金明細を注文と突き合わせる作業はなくなります。

  • 支払いの前に、金額と注文が決まっている。支払いは、最初から 1 つの注文に結びついています。
  • 購入者が振り込む額の過不足が、お店の受け取りに及ばない。照合できない入金が、お店の側に残りません。
  • 成立が注文番号つきで届き、お店が注文に反映できる。届かないときは、お店のサーバーから状態を照会して確かめます。

ここでいう消込が要らないとは、銀行の入金明細と注文を突き合わせる作業がない、という意味です。売上や手数料の記帳、返金の操作、成立の知らせを注文に反映する組み込み（知らせの検証や、届かないときの状態照会）は残ります。

この条件を満たす受け取り方の例は、銀行振込決済とはで、ほかの受け取り方と比べて説明しています。

すてぶるペイの場合

すてぶるペイは、円で払い、ステーブルコイン（JPYC）で受け取る決済です。開発中で、提供開始日は未定です（2026年11月時点）。購入者は日本円の銀行振込とパスキーで支払いますが、振込先はお店の口座ではありません。お店には、購入者が承認した注文の支払いが注文ごとに届き、成立の知らせも注文番号つきで届きます。銀行 API やバーチャル口座で明細を照合するのではなく、支払いが最初から注文に結びついている形です。仕組みと注意点は、銀行振込決済とはにまとめています。

よくある質問

入金消込は自動化できますか？

多くの入金は、自動で照合できます。銀行 API で明細を取り込み、バーチャル口座や照合のルール、消込のシステムを組み合わせます。過不足のある入金や照合できない入金は、決めたルールで処理するか、購入者に連絡して確かめます。返金の手順は、サービスによって違います。自動化の範囲は、本文の表にまとめています。

銀行 API を使えば、消込は全部自動になりますか？

いいえ。銀行 API は明細を速く取る手段で、振込に載る手がかり（振込依頼人名・金額・日付など）を増やすものではありません。例として調べた銀行の仕様書にも、注文番号を入れる専用の欄はありません。銀行 API だけでは、注文や請求との対応が決まらない入金があります。

バーチャル口座のデメリットは何ですか？

注文や取引先ごとに口座番号を分けるので、名義の違いによる照合のずれは減らせます。一方で、額が足りない入金や多い入金は残ります。Stripe の場合、過払いは顧客の残高に残り、顧客の残高が消し込まれているかは、お店の責任で確かめる必要があるとされています。口座の数の上限や、法人口座が前提かどうかなどの条件も、サービスごとに確かめてください。

全銀 EDI（ZEDI）とは何ですか？

全銀 EDI システム（ZEDI）は、振込に添える情報を増やす仕組みで、2018年12月25日に稼動しました。EDI 情報が、20 桁から、XML 形式で 140 桁×最大 500 行に増えました。企業がまとめて振り込む総合振込向けで、受け取る側も対応したサービスが要ります。全国銀行協会の 2019年12月の資料は、当時、利用が進んでいるとは言い難い状況だとしていました。いまの利用状況は、この解説では確かめられていません。

入金消込の自動化が進まない原因は何ですか？

届く情報が、振込依頼人名・金額・日付などに限られるためです。名義の違い、振込手数料の差し引き、まとめての振込などでずれると、システムが一致と判断できないことがあります。EDI 情報で番号を添える仕組みは企業どうしの振込向けで、2019年の資料では、当時、利用が進んでいないとされていました。照合できない入金は、決めたルールで処理するか、購入者に連絡して確かめます。

消込そのものをなくす方法はありますか？

あります。支払いの前に金額と注文が決まっていること、購入者が振り込む額の過不足がお店の受け取りに及ばないこと、成立が注文番号つきで届き、お店が注文に反映できることの 3 つがそろう受け取り方です。銀行の入金明細を注文と突き合わせる作業がなくなります。記帳や返金の操作は残ります。仕組みは、銀行振込決済の解説で説明しています。

すてぶるペイは、円で払い、ステーブルコイン（JPYC）で受け取る決済です（開発中）。購入者は日本円の銀行振込とパスキーで支払い、お店はカード会社の与信審査に頼らずに売上を受け取ります。
