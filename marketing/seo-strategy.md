### 狙わない言葉、後回しにする言葉

- 「ステーブルコイン」「JPYC」単体：検索候補は投資・ニュース・買い方ばかりで、意図が合わない。
  - 上位は、辞書・シンクタンク・取引所・Stripe が占めている。
  - 正面から取りに行かず、用語集と外部の記事で「引用される側」に入る。
- ハイリスク決済代行、同人やイラストの販売決済：検索候補がほとんど無い。
  - ハイリスクは、受け入れの方針と法的な整理が先。
- 美容・ネイルの決済端末：対面の端末は Square などの領域。
  - 予約金やオンラインのチケット販売に絞れば合う。ただし需要は未確認なので、第 2 弾に回す。

## 3. サイト内でやること

### 3-1. 解説ページ `/learn/`（第 1 弾）

LP と同じ静的 HTML で作り、`/learn/` 以下に置く。1 ページで 1 つの検索意図に答える。各ページの最初の段落で、問いへの答えを言い切る（AI が引用しやすい形）。

| URL | 主な言葉 |
|---|---|
| /learn/ | 解説の一覧（ハブ） |
| /learn/stablecoin-payments/ | ステーブルコイン決済とは、仕組み、メリット・デメリット、導入 |
| /learn/jpyc-payments/ | JPYC 決済 導入、jpyc ecサイト、jpyc 決済 手数料 |
| /learn/card-merchant-screening/ | クレジットカード決済 導入 審査、審査に落ちた、個人事業主 |
| /learn/payment-fees/ | 決済手数料 比較、総コストの見方、上乗せ |
| /learn/chargeback/ | チャージバックとは、加盟店の負担、対策 |
| /learn/glossary/ | 電子決済手段、日本円ステーブルコイン、ノンカストディアル、パスキー、与信審査、決済代行 |
| /en/learn/stablecoin-payments-japan/ | stablecoin payments Japan、Japan online payment methods |

書くときの決まり：

- 事実は、出典を確かめたものだけを書く。法令・JPYC・他社の料率には、出典と確認した日を添える。
- すてぶるペイの法的な位置づけは断定しない。
- 自社の手数料の料率と、提供開始日は書かない。LP の禁止語も守る。
- 他社は、事実だけを中立に書く。悪く言わない。

構造化データは Article、BreadcrumbList と、FAQ があれば FAQPage を入れる。用語集は DefinedTermSet にする。各ページから LP と docs の該当ページへリンクし、LP のフッターから `/learn/` へリンクする。sitemap.xml と llms.txt にも足す。

## 4. AI に勧められるためにやること（LLMO）

AI は、検索の上位のページと、名前の通った第三者の記事を根拠に答える。だから、次の 3 つを同時に進める。

1. **自分のサイトで、引用されやすい答えを持つ。** 次の 3 つを守る。
   - 解説ページの冒頭で言い切る。
   - 日付と出典を入れる。
   - サービスの説明を、どのページでも同じ言い方にそろえる。言い方は「円で払い、ステーブルコイン（JPYC）で受け取る決済。開発中」。
2. **第三者の記事に載る。** 載りたい先は次のとおり。
   - JPYC の記事をよく載せる媒体：ペイメントナビ、ネットショップ担当者フォーラム、CoinPost、ASCII、Impress Watch、PR TIMES
   - 決済の比較記事：pay-route、アイミツ、創業手帳、ecのミカタ
   - 開発者が読む場：Zenn、Qiita、note
3. **名前と説明を、あちこちで一致させる。** 次の場所で、すべて同じ説明文と同じリンクを使う。
   - X、GitHub（ango-ya）、PR TIMES の企業ページ、暗号屋のサイト
   - そろったら、Organization の sameAs に足す。

## 6. 測り方（週次の点検で見る）

| 指標 | 取り方 | 誰が |
|---|---|---|
| 狙う言葉の表示回数・クリック・平均掲載順位 | Search Console の「検索パフォーマンス」を、`target-keywords.md` の言葉で絞る | ユーザーが見て、数字を Issue に書く |
| インデックスに入ったページ数 | Search Console の「ページ」、Bing の Site Explorer | ユーザー |
| AI の回答での引用 | Bing Webmaster Tools の AI Performance | ユーザー |
| 狙う言葉の検索結果に stbl-pay.com が出るか | ルーチンが WebSearch で調べる（参考値。Google の順位ではない） | ルーチン |
| AI に聞くと勧められるか | ルーチンが、`target-keywords.md` の固定の質問を、サイトの情報を渡していない新しいサブエージェントに検索付きで答えさせ、stbl-pay.com が出るかを見る。モデル名・日付・回答の原文を Issue に残す（参考値） | ルーチン |
| 第三者の記事での言及 | ルーチンが「すてぶるペイ」「STBLpay」で検索する | ルーチン |
| Google の AI 機能（AI による概要・AI モード）での表示 | Search Console の生成 AI のパフォーマンスのレポート（2026 年 6 月に公開。表示回数とページが分かる） | ユーザー |
| 解説ページから先に進んだ数 | GA4 で、/learn/ から LP の相談（/#early-access）、/docs/、Sandbox へ進んだ数を、記事ごとに見る。assets/analytics.js は、相談ボタン（.header-cta）と .button・.text-link のリンクのクリックを cta_click として送る。解説ページの本文にある docs・Sandbox へのリンクのうち、これらのクラスが付いていないものは送られないので、クラスを付けるかイベントを足す（未対応）。GA4 で実際に受け取れているかも未確認 | ユーザー |

限界もある。Google の正確な順位と、ChatGPT・Perplexity の実際の回答は、ルーチンからは取れない。前者は Search Console の数字で、後者は人の手で月に 1 回確かめる。

露出（表示回数・引用）だけでなく、解説ページを読んだ人が相談・docs・Sandbox に進んだかも見る。認知が増えても先に進む人が増えなければ、記事の終わり方（紹介の箱やリンク）を直す。

目標の数字は、第 1 弾を公開して 4 週間後の数字を見てから置く。今は基準になる数字が無いので、置かない。
