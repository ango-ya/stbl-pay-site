# 返金の提供範囲

**現在の返金は、加盟店コンソールの「取引の詳細」画面から、加盟店の owner がパスキーで承認する経路だけです。** 加盟店サーバーから呼べる返金 API はありません。

- **返金の操作**：加盟店コンソールの「取引の詳細」画面にある「返金」から行う（[手順](/refunds/execute)）
- **承認**：owner のパスキー。承認がなければ返金は実行されない
- **返金先**：元の支払人のウォレットに固定。画面でも API でも変更できない
- **金額**：全額・一部・複数回に分けた返金ができる。決済ごとの合計は元の決済額を超えない
- **加盟店サーバーからの返金**：提供しない。加盟店の API キーでは返金できない

加盟店サーバーの鍵で返金を実行する機械返金（`@stbl-pay/refund-sdk` を含む）は、提供していません。

## 返金と決済の状態

返金は元の決済を `canceled` に戻す操作ではありません。元の決済は `settled` のままで、決済の状態も `payment.*` の Webhook も変わりません。**返金の完了を知らせる Webhook はありません。** 結果は取引の詳細画面の返金の履歴で確認してください。

## 加盟店サーバーとの関係

返金を始める契機は、注文管理システムなど自社側で決め、運用担当者が加盟店コンソールで操作します。自社の注文を返金済みにする更新は、コンソールの履歴で `返金完了` を確認してから行ってください。

[返金の手順](/refunds/execute)、[返金できる額と原資](/refunds/funding)、[返金できないとき](/refunds/errors)を参照してください。
