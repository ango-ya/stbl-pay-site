# 返金できないとき

返金を始められないときは、「返金」の画面に理由が出ます。

| 画面の表示 | 対処 |
|---|---|
| 完了した決済だけ返金できます | 決済が `settled` になってから操作する |
| お客さまの受取先が分からないため返金できません | 加盟店側では解決できません。決済 ID を添えて[問い合わせ先](/support/troubleshooting#問い合わせ先)に問い合わせる |
| いま返金できる額がありません | 返金済みで残りがない。または、受取ウォレットの残高やチェーン上の返金の裏付けが 0 になっている。画面に併せて出る理由の文と、履歴を確認する（理由の文が出ていれば[返金できる額と原資](/refunds/funding)を参照） |
| 進行中の操作の確認後に返金できます | ウォレットの別の操作が進行中。確認が終わってから再確認する |
| 承認待ちの操作があります | 承認待ちを取りやめるか、しばらくしてから再確認する |
| 受取ウォレットがまだ作成されていないため返金できません | 受取ウォレットが作成されてから再確認する |
| 状況を確認できないため、今は返金できません | しばらくしてから「再確認」を押す |

組み立てや承認の段階で拒否されたときも、画面に理由が出ます。ウォレットのアップデートが要るときは、画面から「アップデートへ」進めます。返金額が返金できる額を超える、受取ウォレットの残高が足りない、といった拒否も同じです。コンソールでは画面の案内に従ってください。

## 結果が分からないとき

返金の承認後に通信が失敗したり、画面を閉じたりしても、返金は受け付けられているかもしれません。「返金されていない」と決めつけて、もう一度返金しないでください。取引の詳細を開き直すと、サーバーの記録から進行中の返金が再び表示されます。「結果確認中」の間は、新しい返金を始められません。


## サーバー連携のエラー（公開準備中）

401 `auth/api_key_invalid`・`auth/machine_signature_invalid` は鍵と署名を確認します。`auth/replay` はnonceの使い回しです。419 `auth/clock_skew` は時計補正後に新nonceで一度だけ再送します。409 `member/not_active`・`member/revoked`・`delegation/stale` はownerの確認が必要です。`refund/exceeds_delegation_cap` は委任上限を確認します。`store/disabled` では新規実行を止めます。未知のコードは共通のフォールバックへ落とします。通信結果が不明なら[復旧手順](/refunds/machine-api#通信結果が不明なとき)に従って照会します。
