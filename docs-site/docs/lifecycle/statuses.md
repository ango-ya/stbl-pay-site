# ステータス一覧

決済の状態は **11種類**です。通知の配信成否はこの状態に含まれません。

| 状態 | 区分 | 意味 |
|---|---|---|
| `created` | 途中 | 決済意図を作成し、署名を待っている |
| `signed` | 途中 | 利用者の署名と、支払い操作の内容の保管が完了した |
| `issue_pending` | 途中 | 決済ページから予約開始の通知を受けた。JPYC EX での手続きが済んだことは意味しない（途中でやめてもこの状態になる） |
| `deposit_confirmed` | 途中 | 着金が取り消されない状態になった、または残高払いで残高が足りることを確認した。実行前 |
| `deploying` | 途中 | 必要なウォレットを作成し、できたかを確認中。準備が整うと `deposit_confirmed` に戻る |
| `executing` | 途中 | STBLpay が決済の実行を始め、結果を確認中 |
| `settled` | 終端 | 決済実行が成功し、加盟店送金と手数料分配が完了した |
| `canceled` | 終端 | 利用者がマイページで決済を取り消した |
| `expired` | 終端 | 期限が来て終了した。操作期限までに承認されなかった場合、承認したあと JPYC EX の手続きへ進まないまま操作期限が来た場合、着金期限までに支払える額がそろわなかった場合がある |
| `failed` | 終端 | 決済が成立せずに終わった。理由は `failedReason`（[分類コード](/reference/rest#failed_reason-の分類コード)） |
| `nonce_conflict` | 終端 | 送金の結果を確定できないまま、確認の上限に達した。送金が行われたかどうか、成功したか失敗したかは分からない。番号（nonce）を読む通信の失敗が上限まで続いた場合も含む。運用調査が必要（[詳細](/lifecycle/transitions#技術的な詳細)） |

「終端」「成立」「決済意図」などの語は[用語集](/reference/glossary)にあります。

`failed` になる主な理由は、宛先の不一致、実行前の確定的な失敗、実行の失敗、再試行の上限、加盟店の利用停止などです。着金または残高の充足を確認した後に実行期限を過ぎた決済は、`expired` ではなく `failed`（`userop_expired`）になります。

`settled` だけが成立です。署名・着金確認・送信完了だけで商品を提供しないでください。

## 終端状態

終端に到達した決済は、ほかの状態へ遷移しません。**`canceled` から `settled` へ復活することはありません。** 後から発行された資金は利用者のウォレットに残ります。

外部の発行予約の取消操作を STBLpay が観測できず、決済が `issue_pending` のままである場合とは区別してください。詳しくは [異常系](/lifecycle/edge-cases)にあります。

`nonce_conflict` は自動的な支払い成功・失敗の判断に使わず、[状態照会](/server/retrieve-payment)と調査につなげます。

## 未知の値・照会エラー

通信失敗は決済状態ではありません。未知の値を受け取った場合も、商品提供や再請求を行わず確認中として扱い、[問い合わせ先](/support/troubleshooting#問い合わせ先)に確認します。

次は [状態遷移と期限](/lifecycle/transitions)を参照してください。
