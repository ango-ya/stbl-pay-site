# お金の流れ

利用者は JPYC で支払い、加盟店は JPYC で受け取ります。JPYC 残高が足りない利用者は、支払いを承認したあと JPYC EX で発行を申し込み、日本円を払い込んで JPYC を用意します。ここでは、JPYC が利用者から加盟店に届き、円に戻るまでを説明します。語の意味は[用語集](/reference/glossary)にあります。

## 使うもの

- **JPYC**：1 JPYC ＝ 1 円の、日本円建てのステーブルコインです。STBLpay の決済は JPYC で行います。
- **JPYC EX**：JPYC の発行と償還（円に戻すこと）を行う、発行体のプラットフォームです。利用者や加盟店は JPYC EX と直接やりとりし、STBLpay は間に入りません。
- **Polygon**：JPYC が動くブロックチェーンです。利用者のウォレットも、加盟店の受取ウォレットも Polygon 上にあります。

## 流れ

1. **利用者が支払いを承認する。** 利用者は決済ページで、支払いの内容をパスキーで承認します。この時点では、まだ JPYC は動きません。
2. **JPYC がそろったら、STBLpay が送金する。** 利用者のウォレットの JPYC が決済額に足りていれば、STBLpay がそれを確かめて送金を実行します。足りない利用者は、承認のあと決済ページから JPYC EX の手続きへ進み、JPYC の発行を申し込んで銀行振込で円を払い込みます。振込が確認されると JPYC EX が利用者のウォレットに JPYC を発行し、今の残高と合わせて足りた時点で、STBLpay が送金を実行します。送金では、利用者のウォレットから加盟店の受取ウォレットへ JPYC が送られ、STBLpay の手数料は同じ取引の中で差し引かれます。
3. **加盟店の受取ウォレットに JPYC が届く。** 届いた額（手数料を引いたあと）は、`payment.settled` の Webhook の `net_received_jpy` で確認します。Webhook を設定していない場合は、加盟店コンソールのメニューの「お店と QR コード」から店舗を開き、「この店舗の売上」タブで取引の「詳細」を開いて、「取引の詳細」画面の「お受け取り額」で確認します。使うのは成立（`settled`）した取引の額だけにしてください。成立していない取引では見積りの額が出ます。状態照会には金額がなく、作成応答の `netAmountJpy` は作成時の見積りで実際の受取額と違うことがあるため、受取額の確認には使えません。失敗・取消・失効の通知では `"0"` なので、入金の計上には使いません。届いた JPYC は受取ウォレットに残り、[返金](/refunds/overview)の原資にもなります。
4. **加盟店が JPYC を円に戻す。** 受取ウォレットの JPYC を、JPYC EX で償還して円にします。加盟店コンソールの「引き出し」で JPYC EX にログインして償還を申し込み、申し込んだ額の JPYC を受取ウォレットから JPYC EX へ送ります。送るときは owner のパスキーで承認します。送り先は JPYC EX の償還先に限られます。いまご利用いただけるかは、[問い合わせ先](/support/troubleshooting#問い合わせ先)でご確認ください。

例：利用者が 4,980 円の注文を、JPYC 残高 0 の状態で支払う場合

1. 利用者が決済ページで、パスキーで承認する。
2. 利用者が決済ページから JPYC EX の手続きへ進み、4,980 円分の発行を申し込んで、4,980 円を銀行振込する。
3. 利用者のウォレットに 4,980 JPYC が発行される。
4. STBLpay が着金を確かめて送金を実行し、4,980 JPYC から手数料を引いた額が、加盟店の受取ウォレットに届く。

## 受取ウォレット

- 加盟店ごとに 1 つある、Polygon 上のウォレットです。加盟店の owner のパスキーにひも付いています。
- アドレスは、Webhook の `payout` に入っています。
- ウォレットは、最初の決済のときに作られます（状態が `deploying` を経ます）。
- 受取ウォレットから JPYC を動かすには、owner のパスキーによる承認が必要です。STBLpay が単独で動かすことはできません。
- owner のパスキーを失くすと、受取ウォレットの JPYC を動かせなくなります。STBLpay でも元に戻せません（パスキーの再設定は[今後の予定](/support/roadmap)です）。パスキーは、ほかの端末と同期される保存先（iCloud キーチェーン、Google パスワード マネージャーなど）に作ってください。同期されていないパスキーには、加盟店コンソールの画面に注意が出ます。
- このパスキーを使える人は、誰でも加盟店コンソールにログインし、返金を承認できます（引き出しも同じです）。使えるのは、パスキーが入った端末（同期した場合は同期先の端末も）で、ロックの解除や PIN の入力ができる人です。売上を扱う人以外が使わない端末で管理してください。スタッフに権限を分けて任せる機能も、[今後の予定](/support/roadmap)です。
